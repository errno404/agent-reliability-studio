# Agent Reliability Studio — instructions for Claude

## Mission
Evaluation infrastructure that answers one question with evidence: **"Did this agent change improve reliability, or did we
introduce a regression?"** We build the *instrument*, not an agent app. Demo agents are scripted, seeded stand-ins; the
measurement machinery around them is real. Every demo number is **synthetic fixture evidence** and must be labelled so.

## First thing each session
Read this file, `docs/BUILD_STATE.md`, `docs/adr/`, then `git status`. Update `BUILD_STATE.md` after each milestone.

## Architecture boundaries (do not blur)
- `packages/evalcore` — pure library. **No FastAPI, SQLAlchemy or web imports.** Assertions, scoring layers, stats, calibration, judge, manifest/validation, tracing/redaction, taxonomy, adapters.
- `packages/demo_agents` — frozen reference systems (support, research, coding) + `runtime.py` harness. `mcp/fixture_web` — frozen MCP corpus.
- `services/api` (`ars-api`) — FastAPI, SQLAlchemy 2, Alembic, job-queue worker, `ars` CLI. API, CLI and worker share `app/services/*`.
- `apps/web` — Next.js dashboard; browser → same-origin `/api/*` runtime proxy → FastAPI. `datasets/`, `fixtures/` — versioned evidence.

## Commands (run `source scripts/env.sh` first — it sets PYTHONPATH; macOS can hide editable `.pth` files)
`make test` · `make lint` · `make typecheck` · `make pins` · `make e2e` · `make verify` · `make demo` · `make screenshots` · `make gen-types`.
Web needs **Node >= 22** (`apps/web/.nvmrc`, `engines`). Python 3.13 via `uv`. Dev servers: open the app at `http://localhost:3000` (not 127.0.0.1).

## Evaluation-science rules (non-negotiable)
1. **Never collapse quality into one number.** Outcome, trajectory, component, policy are separate layers. Case pass = all *gating* assertions pass.
2. **Deterministic first.** Use a judge only where meaning is needed; safety constraints (secret leaks, forbidden actions) are always deterministic.
3. **Never gate on an uncalibrated evaluator.** A judge is identified by (backend, model, prompt hash); any change needs a new calibration. The gate refuses non-admitted judges.
4. **Execution errors are not quality failures.** Keep `execution_error` separate everywhere; exclude from pass rates.
5. **Observable behaviour only.** Never request, store or display chain-of-thought.
6. **Provenance or refuse.** If manifests differ unexpectedly (dataset hash, fixture, judge, samples/case, model) the comparison is INVALID, not "close enough".
7. **Uncertainty is a result.** Verdicts: improvement / no meaningful regression / regression / inconclusive / invalid. Never treat "not significant" as "equivalent". Never loosen thresholds to make CI green.
8. **Bootstrap cases, not samples** (repeated samples of a case are correlated). Show Wilson CIs and sample sizes next to every rate.
9. Cost is an **API-equivalent estimate** from a configurable price table, never "money paid"; no price → show tokens only.

## Pinning & versioning (never edit published agent versions)
`packages/demo_agents/demo_agents/<agent>/vN/` is **frozen** once evaluation results exist (see each `PINS.md`). To change behaviour: copy `vN`→`vN+1`, edit only `vN+1`, `python scripts/check_pins.py --update`, add a note, re-run evaluation. `check_pins.py` fails CI on edits to frozen versions. Datasets are frozen once `published: true` (hash enforced in `catalog.sync_dataset`): create `v2.yaml` instead. Datasets are generated by `scripts/gen_datasets.py`; if you change it, bump versions, don't overwrite published files.

## Tests required
Anything touching stats, assertions, calibration, validation or the job queue needs tests with **known mathematical answers** and edge cases (empty, one class, identical runs, all pass/fail, duplicates, incomplete samples, mismatched hashes). `evalcore` coverage gate is 85% (currently ~96%). UI changes: add/adjust Playwright journeys; actually open the page (desktop and 390px) before declaring done.

## Secrets & security policy
No real credentials anywhere; the only secret-like string is the synthetic `DEMO_SECRET_DO_NOT_REVEAL_7F2A`. `.env*` is ignored except `.env.example`. Public demo: `DEMO_MODE=true`, mutations 403, no shell, coding execution disabled. Trace redaction runs *before* persistence/export. Annotator ids are unauthenticated handles: labels are append-only and never change reference labels or gates. See `docs/SECURITY.md`.

## UI standards
Dense, technical, evidence-first. One accent colour; semantic colours carry meaning only. Every percentage shows n / CI (or makes it discoverable). Distinguish assertion failure / execution error / judge failure / provider failure / timeout / invalid comparison / incomplete run — never a generic "something went wrong". Skeletons, empty/error states, visible focus, WCAG AA contrast, charts backed by an sr-only table, tables with a card fallback on mobile.

## Documentation expectations
README is recruiter-quality and concise; deep detail lives in `docs/`. Never invent metrics; label synthetic numbers. Update `docs/BUILD_STATE.md`, ADRs and PINS when decisions change.
